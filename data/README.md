# Survey data

This folder is the only place the team needs to touch. Everything else is generated.

```
data/
├── raw/              # drop WiGLE CSV exports here — one file per survey session
├── campus_bbox.json  # study-area box; observations outside it are ignored
└── processed/        # GENERATED by scripts/build.py — never hand-edit
    ├── fixes.geojson   one point per GPS fix
    ├── grid.geojson    one polygon per 25 m grid cell
    └── summary.json    counts, date range, devices, config the map reads
```

## How to add a survey

1. In the WiGLE Wifi Wardriving app, export the run as **CSV** (Database → Export / Backup → CSV).
   Do not edit the file; the build script expects WiGLE's own column layout.
2. Rename it to the pattern below and copy it into `data/raw/`:

   ```
   YYYY-MM-DD_<area>_<device>.csv
   ```

   | part | what to put | examples |
   |---|---|---|
   | `YYYY-MM-DD` | date of the survey (or export date if the file spans several days — observation dates always come from the `FirstSeen` column, not the filename) | `2026-11-04` |
   | `<area>` | one word for where you walked, no underscores | `monroe-park`, `mcv`, `cabell`, `broad-st` |
   | `<device>` | which phone/node collected it, no underscores. Be consistent — the map lets you filter and compare by device | `pixel7-alex`, `s23-jordan`, `meshtastic-node2` |

   Examples: `2026-10-21_monroe-park_pixel7-alex.csv`, `2026-11-04_mcv_s23-jordan.csv`

3. Commit and push to `main`. The GitHub Action rebuilds `processed/` and the site updates in a minute or two.
   You can also rebuild locally with `python3 scripts/build.py` (no dependencies beyond Python 3.10+).

Overlapping exports are fine — identical observations (same AP, time, place, RSSI) are de-duplicated.
Never push anything that hasn't been through the team's consent/cleaning step.

## Column dictionary (WiGLE CSV)

| column | type | used? | meaning |
|---|---|---|---|
| `MAC` | string | yes | BSSID of the access point. Used for de-duplication. |
| `SSID` | string | yes | Network name. Campus networks recognised by the build: `VCU SafeNet Wireless`, `eduroam`, `VCU Guest Wireless` (edit `CAMPUS_SSIDS` in `scripts/build.py` to change). Empty = hidden network. |
| `AuthMode` | string | no | Security capabilities, e.g. `[WPA2-EAP…][ESS]`. |
| `FirstSeen` | `YYYY-MM-DD HH:MM:SS` local | yes | When the observation was logged. Rows dated `1970-01-01` are GPS-clock glitches: kept, but with no date. |
| `Channel` | int | no | Wi-Fi channel (band is derived from `Frequency` instead). |
| `Frequency` | int, MHz | yes | `< 3000` → 2.4 GHz, `< 5925` → 5 GHz, else 6 GHz. |
| `RSSI` | int, dBm | yes | Signal strength as seen by the phone. Higher (closer to 0) is stronger. Typical range −30 (next to the AP) to −90 (barely detectable). |
| `CurrentLatitude`, `CurrentLongitude` | float, WGS84 | yes | Phone position at the time of the observation. |
| `AltitudeMeters` | float | no | |
| `AccuracyMeters` | float | yes | GPS horizontal accuracy (usually 5–20 m). Shown in fix tooltips. |
| `RCOIs`, `MfgrId` | string | no | Passpoint roaming IDs, manufacturer ID. |
| `Type` | string | yes | Only `WIFI` rows are used; `BT`/`CELL` rows are dropped if present. |

## How the build turns rows into a map

- **Fix** = all rows sharing one `(lat, lon, FirstSeen)`. WiGLE writes several rows (one per network) at each scan, so a fix is one place-and-moment. For each fix the build records the strongest RSSI per campus SSID per band.
- **Cell** = 25 m × 25 m square on a grid anchored at the south-west corner of `campus_bbox.json`. A cell's value is the **median** of its fixes' best campus RSSI.
- **Tiers:** excellent ≥ −65 dBm · good −65 to −75 · fair −75 to −85 · poor < −85 · **none** = surveyed but no campus SSID logged · gray = never surveyed. Edit `TIERS` in `scripts/build.py` to change the thresholds.

## Important caveat about "dead spots"

WiGLE normally logs each network **once per run** (at the point it was first/best seen) rather than every scan. That means a fix with no VCU row may simply be a place where the phone had *already* logged the nearby APs a minute earlier — not a place with no signal. Treat red "no campus Wi-Fi observed" cells as **candidates to re-survey**, and give the most weight to cells that stay red across several dates and devices.

To get true per-scan observations, check your WiGLE settings for an option to log every observation rather than only new networks, or pair WiGLE with a tool that logs RSSI continuously. The build script will work unchanged with denser data — it just gets more accurate.

Other limits worth stating in any write-up: readings are from phones on sidewalks (not indoors), different phones have different antennas (hence the device filter), and ~8 m GPS error makes anything finer than the 25 m grid misleading.
